# AINPC 作者约束的角色交互

[English](README.md)

本页介绍研究原型的思路与当前进展，不提供可运行软件包或完整研究材料。

[项目网页](https://ruixiaozhang.com/#work-ainpc)

如何让游戏角色自由回应情境，同时让世界的作者保留对角色行动的控制？

## 问题从哪里来

我用餐厅原型把这个问题具体化。例如，角色可能回答得很有说服力，却试图使用已被占用的座位，或忽略先前作出的承诺。前者可能违反明确规则；后者即使被系统允许，也可能不符合作者对情境的判断。因此，我分别检查动作是否被允许，以及它是否符合作者的意图。

## 从对话走向行动

为保留这条边界，我让语言模型以结构化数据提出台词、意图和高层动作，由 Unreal Engine 控制移动、交互和世界状态的改变。模型的提议与引擎实际执行的动作由此可以分开检查。

在已实现的路径中，本地校验先结合作者约束和当前场景状态，检查目标是否存在、资源是否空闲、交互是否允许，再处理模型的提议。拒绝、兜底和执行结果都会留下记录，供后续检查。这些路径仍在扩展，原型尚不能保证每一种提议都能得到成功的修复。

执行本身也需要单独管理，因为模型回复与角色动画的完成时间并不一致。在已实现的路径中，运行时跟踪动作的开始与结束，收到引擎侧确认后才记录完成。语音合成和字幕负责呈现对话，移动与落座则由各自的执行任务处理。角色说自己做完了某件事，不能代替世界状态中的完成证据。

## 研究具体检查什么

在区分提议与执行之后，我还需要检查用于评价动作的判断：自动化判断能否反映作者在具体情境中的区分？回答这个问题，不等于证明引擎执行成功，也不等于证明玩家体验改善。本页介绍研究问题和原型思路，详细评估规则、数据与研究结果暂不公开。

## 走进原型场景

### 角色共享的世界

![角色共享的世界](docs/media/ainpc-dining-room.jpg)

餐厅把角色、桌椅与公共空间放进同一个场景，为研究对话如何连接到受规则约束的行动提供具体语境。

### 有身体与位置的对话

![有身体与位置的对话](docs/media/ainpc-conversation.jpg)

角色落座后，对话有了具体的空间关系。语音、字幕、姿态和移动分别由原型中的不同部分处理；画面展示的是交互环境，交互质量仍需评估。

### 物件也是交互条件

![物件也是交互条件](docs/media/ainpc-booth.jpg)

桌椅是角色需要操作的对象，不能只作为布景处理。后续工程将继续检查角色意图能否对应到有效目标，以及执行后能否观察、确认预期的变化。
